# SS Wayfarer / Living Crew expansion
Additive kit; keep the original Command Deck and other asset archives. **Do not replace the room layout or duplicate the assembled bridge's existing droids.** Remove or hide only the old static/operator droid meshes before enabling these ten persistent agents. Existing console and chair placements remain authoritative.

## Bind production data
1. Use `src/roster.mjs` for six droids and four cats. `demoLayout` is strictly an illustrative test graph, never use it as the ship's real coordinates. Build `layout.nodes` keyed by ID: `{x,y,z,room}`. Add floor-center waypoints, separate door approach nodes on each side, and corridor junctions. `layout.edges` uses `{a,b,door?}` where `door` is the real door ID; only mark the actual threshold-crossing edge. Validate clearance and line of sight against the existing navmesh/collision shapes. Add distinct safe cat rest/explore/social spots and approach anchors within 0.5–0.8m of standing droids. `layout.spots`: `{node,room,type}`. Avoid dead-end nodes occupied by agents.
2. `layout.stations`: six `{id,node,owner,type:'seat',yaw}` (actual seated pelvis alignment), six `{id,node,owner,type:'console',yaw,asset,placement:{x,y,z,yaw}}`. `node` is the standing/seat foot position, not the panel center. Roles: nav → Holodeck; eng → corridor maintenance alcove; sci → Library; com → Lounge; tac → Media Nexus; sen → Holodeck. These assignments are suggestions, not new room construction. Place panels on free walls, keeping door access clear. Existing `Console_*.glb` and chair files are copied for convenience; avoid duplicate props. `mountSatelliteConsoles` places only entries with explicit `placement`. Register panel collision geometry separately.
3. Import `mountLivingCrew` from `src/three-adapter.mjs`. Inject existing THREE, GLTFLoader, scene, validated layout, and host hooks. Await loading. `host.player()` returns `{x,y,z,radius}`; `host.canMove(n,p)` must perform swept capsule/navmesh and static geometry tests including doors; `host.canInteract(n,p)` checks unobstructed ray/room. `host.doorState(id)` returns `open`, `closed`, or `locked`. `host.requestDoor(id,npc)` calls the actual opening system; it must be idempotent. The engine waits for open before crossing, reroutes on locked or timeout. Keep player physics authoritative: block the player's capsule against the NPC capsules and call `crew.bump(id)` on actual impact; don't push through characters.
4. In existing update loop call `crew.update(deltaSeconds)`. Click/tap: call `crew.click({ndc,camera})` after UI and world occlusion checks; within 2.3m and LOS triggers dialogue or petting. The adapter delegates actual cinematic framing to `host.dialogueCamera({active,npc,object})`, and player lock to `host.setPlayerInputEnabled(enabled)`. Implement a damped shoulder/medium close-up using current player/camera state, restore on exit. Optional `createDialoguePanel(hud)` from `dialogue-ui.mjs`; connect its `show/hide` to `host.showDialogue/hideDialogue`. Add Escape/back close and handle app suspension. No HTML artifact or replacement game is provided.
5. Feed live `crew.engine.setShip({mode,destination,alert,fault})`. `crew.save()` returns JSON-safe memory, needs, ship state, and last waypoint; merge into existing save system. Restore on mount via `saved`. In-flight agents resume from their last confirmed waypoint, not mid-animation; no offline simulation. Never spawn twice. Persist in actual save slot, not a global overwrite.
6. Hook `host.playSpatialSound`, `host.speak`, `host.crewChat`, `host.onCrewEvent` and missing clip diagnostics. Optional `audio.mjs` generates synthetic placeholder sounds only; replace with real feline audio and voice lines. `host.speak` may use device TTS or recorded voice, but the deterministic branching system works offline without an LLM.

## NPC engine
Dijkstra routing on an authored graph; weighted decisions, staggered roaming, station reservations, blocked-route timeout, player-aware yielding, geometry adapter, two concurrent off-station droids, two moving cats, session-limited social interactions, seeded RNG, energy and affection, persistent last order/meeting/pet count and limited event history. Droids work standing at remote consoles, resume home seats when idle, and may pause to socialize. Cats roam accessible rooms, rest, play, groom, approach crew and vocalize after randomized 360–840 seconds. Petting and crew chats use paired states and proximity checks, not IK. Model clips are in-place; foot and hand contact need tuning in real scene. Droids should not clip through seats or walls; production physics checks are mandatory. Cat models are original stylized articulated proxies, not production-quality furry meshes. Camera choreography, voice/audio, UI and door behaviors require host hooks. Only alert state/destination/fault fed from actual gameplay are authoritative; no fabricated discoveries. Dialogue has six choices and role-aware responses; extend via ship event data. No online AI required.
